# 跨平台支持规范

当前支持：Windows（完整）/ macOS（启动器 + GUI 壳）/ Linux（启动器）。

## 支持矩阵

| 能力 | Windows | macOS | Linux |
|---|---|---|---|
| launcher CLI | ✅ | ✅ | ✅ |
| 桌面 EXE | ✅ WebView2 | ❌（用 .app 壳 + 浏览器） | ❌ |
| 安装程序 | ✅ Setup.exe | ✅ scripts/macos | ✅ scripts/macos |
| 自检 | ✅ | ✅（Node/pnpm/DSH 检测） | ✅ |
| 拉起官方 DSH | ✅ DSH Desktop.exe | ✅ .app / dsh CLI | ✅ dsh CLI |

## macOS 使用

### 环境准备
```bash
bash scripts/macos/setup-macos.sh
```

### 启动（GUI 壳）
```bash
bash scripts/macos/start-macos.command
```

### 生成 .app
```bash
bash scripts/macos/build-macos-app.sh
open dist/DSH-Hotplug-Hub.app
```

## 跨平台注意事项

- `launcher/core.js` 已支持 `IS_WIN` / `IS_MAC` 分支。
- macOS 下 `findOfficialHarness()` 会找：
  - `/Applications/DSH Desktop.app`
  - `/Applications/DeepSeek Harness.app`
  - 找不到则回退 `dsh` CLI。
- 链接类型：Windows 用 junction，macOS/Linux 用目录符号链接。
- GitHub Actions 已增加 `macos-latest` 运行启动器测试。

## 禁止
- 禁止在跨平台代码里写死 Windows 路径（`C:\`、`%LOCALAPPDATA%`）。
- 禁止假设 pnpm 是 `.exe`（Windows 是 `.cmd`，macOS/Linux 是 shell 脚本）。
- 新增平台相关逻辑必须同时更新本规范和 README。
