# 开发踩坑记录

> 按目录和功能分类，记录本项目开发过程中踩过的坑与解决方案。
> 新成员/AI 修改前先看这里，避免重复踩坑。

## 1. 桌面端（release/）

### 1.1 WebBrowser 全白
- **坑**：用 WinForms WebBrowser（IE 内核）打开现代 HTML，页面全白。
- **原因**：IE 不支持现代 JS（箭头函数、模板字符串、CSS 变量等）。
- **解决**：改用 **WebView2**（Chromium 内核），原生桌面窗口渲染。

### 1.2 Edge app 模式被当成浏览器
- **坑**：用 `msedge --app` 启动，用户认为是“打开浏览器”。
- **解决**：改用 C# WinForms + WebView2 内嵌窗口，不启动浏览器。

### 1.3 自检 pnpm 未检测到
- **坑**：Windows 下 pnpm 是 `pnpm.cmd` / `pnpm.ps1`，直接 spawn `pnpm` 失败。
- **解决**：多路探测：
  - `cmd.exe /c pnpm --version`
  - `pnpm.cmd --version`
  - `%APPDATA%\npm\pnpm.cmd`

### 1.4 dsh 版本显示错误（rc.8）
- **坑**：界面显示写死的假版本 `0.1.0-rc.8`。
- **解决**：读取官方 DSH：
  - `%LOCALAPPDATA%\Programs\DSH Desktop\resources\app\package.json`
  - 取 `dependencies["@deepseek-ai/dsh"]` → 真实 `0.1.0-rc.7`

### 1.5 WebView2 DLL 被占用/覆盖
- **坑**：编译时 `Microsoft.Web.WebView2.*.dll` 被运行中的 EXE 占用，或本地 Office DLL 覆盖了仓库版本。
- **解决**：
  - 编译前杀掉 `DSH-Hotplug-Hub.exe` 和 `msedgewebview2.exe`
  - 构建脚本支持环境变量 `WEBVIEW2_CORE_DLL / WEBVIEW2_WINFORMS_DLL / WEBVIEW2_LOADER_DLL`（CI 用）
  - 编译后还原仓库里的 DLL，避免误提交

## 2. 启动器（launcher/）

### 2.1 跨平台路径
- **坑**：Windows 用 `junction`，macOS/Linux 需要用目录符号链接。
- **解决**：`launcher/core.js` 用 `IS_WIN / IS_MAC / process.platform` 分支。

### 2.2 找不到官方 DSH
- **坑**：macOS/Linux 没有 `DSH Desktop.exe`。
- **解决**：
  - macOS：找 `/Applications/*.app`
  - Linux：找 `/usr/local/bin/dsh`、`/usr/bin/dsh`
  - 找不到回退 `dsh` CLI

### 2.3 生成文件污染仓库
- **坑**：`assemble` 测试会生成/更新时间戳 `resolvedAssembly.json`，导致 git 一直脏。
- **解决**：加入 `.gitignore`：
  ```
  assembly/*/resolvedAssembly.json
  ```

## 3. 安装程序（installer/）

### 3.1 Setup.exe 必须放在仓库 installer 目录运行
- **坑**：安装程序用“安装程序所在目录的父目录”作为源根目录，拷到别处会找不到 `release/DSH-Hotplug-Hub.exe`。
- **解决**：固定结构 `installer/Setup.exe`，源根目录 = `installer` 的上一级。

## 4. 文档与团队协作（开发文档/）

### 4.1 文档目录混乱
- **坑**：个人文档散落在根目录，出现 `开发文档2/`、`开发文档3.txt` 等。
- **解决**：统一目录：
  - 个人文档：`开发文档/团队/开发文档N.md`
  - 规范：`开发文档/规范/`
  - 索引：`开发文档/README.md`

### 4.2 重复文档/重复标题
- **坑**：`开发文档3.txt` 与 `开发文档3.md` 重复；`## 详细上传位置` 出现两次。
- **解决**：删除旧 txt，保留 md；按 `文档格式规范.md` 检查标题唯一。

### 4.3 修改前不检查最近改动
- **坑**：多人同时改一个文件，产生冲突。
- **解决**：修改前运行：
  ```powershell
  pwsh -File scripts/check-recent.ps1 -Path <文件>
  ```

## 5. Git / GitHub

### 5.1 Token 缺 workflow 权限
- **坑**：push `.github/workflows/ci.yml` 报错：
  ```
  refusing to allow a Personal Access Token ... without workflow scope
  ```
- **解决**：Token 需要勾选 `workflow` 权限。

### 5.2 pull --rebase 有未暂存修改会失败
- **坑**：本地有未提交修改时 `git pull --rebase` 报错。
- **解决**：先 `git stash` 或提交，再 pull。

### 5.3 直接 push main 绕过保护
- **坑**：Owner 直接 push main，GitHub 提示 Bypassed rule violations。
- **解决**：规范走 PR；或者团队信任时关闭 PR 要求。

### 5.4 CODEOWNERS 需要分支保护才生效
- **坑**：只加了 CODEOWNERS 文件，不生效。
- **解决**：在 GitHub Settings → Branches → 给 `main` 开启：
  - Require a pull request before merging
  - Require review from Code Owners

## 6. API 与自检

### 6.1 自检假数据
- **坑**：原型里写死 Node/pnpm/DSH 版本。
- **解决**：EXE 注入真实检测：Node、pnpm、WebView2、官方 DSH、profile。

### 6.2 自更新检查需要 Release
- **坑**：GitHub 没有 Release 时，`/releases/latest` 返回 404，显示“未获取”。
- **解决**：发版时创建 tag `v0.x.x` 并发布 Release。

## 7. 安全

### 7.1 API Key 不能进仓库
- **坑**：Token / API Key 出现在聊天、日志、配置文件。
- **解决**：
  - `.gitignore` 排除本地配置
  - 密钥只放 `~/.dsh/.credentials.yaml`
  - 泄露后立即 Revoke

## 8. 跨平台

### 8.1 写死 Windows 路径
- **坑**：`C:\`、`%LOCALAPPDATA%` 写死在跨平台代码里。
- **解决**：用 `os.homedir()`、`process.env` 分平台判断；规范见 `开发文档/规范/跨平台支持规范.md`。
